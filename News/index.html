Microsoft 365: Phishing using fake Microsoft 365 outage notices surged after the outage

KnowBe4 Threat Lab says outage-themed phishing peaked on November 13, the second day of the November 12-13 Microsoft 365 outage (MO1550821). On that day detections reached about 468 times the November 9-11 daily average. The lures came in four themes: held messages, a fake security check, an Exchange service notice and a Teams/Planner notification. Some quoted the real incident number, and all of them tried to steal sign-ins through credential harvesting or device code phishing.

All users: Phone callers talk staff into logging in and approving MFA

Okta says the cluster O-UNC-053, previously linked to ShinyHunters, phones employees and talks them into entering credentials on phishing pages and approving MFA prompts or sharing codes. The group steals SaaS data, extorts victims and has posted listings on the new INCEPTION leak site since November 16. Its campaigns have run since October 2026 and use legal-themed lookalike domains such as "legal-<target>". The phishing kit reportedly cannot bypass phishing-resistant methods such as passkeys.

Synology DSM: PHP package updates fix use-after-free and session file flaws

Synology-SA-26:22 is rated Important and lists seven PHP CVEs, but only two affect Synology: CVE-2026-129481, a use-after-free (Important), and CVE-2026-126714, partially overwritten session files (Low; mitigation is session.upload_progress.enabled = 0). The fixed versions are PHP 8.2.36-0172 or later on DSM 7.2+, 8.3.37-0052 or later and 8.4.28-0052 or later. The advisory says nothing about exploitation in the wild.

Entra ID: Connect Health API flaw exposed tenant metadata and admin emails

Since July 23, 2026, a flaw in the Entra Connect Health API let an unauthorized party read tenant metadata: admin email addresses, tenant IDs, domain names and sync status. Microsoft says no passwords, tokens or keys were exposed, and it deployed a server-side fix on November 19. It recommends phishing-resistant MFA for admins, PIM and reviewing sign-in and audit logs. It also says to check the notice in Azure Service Health rather than through email links.
